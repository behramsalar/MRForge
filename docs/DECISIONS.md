# Decisions

Format: date, decision, reason.

| Date | Decision | Reason |
|---|---|---|
| 2026-10-03 | App name is **MRForge** (CLI `mrforge`, outputs in `derivatives/mrforge/`). | User choice. Replaces the `mriapp` placeholder. |
| 2026-10-03 | Python packages are installed in the user's venv `~/progders` (Python 3.13). Project requires Python >= 3.11. | User instruction. |
| 2026-10-03 | Test data lives outside the repo at `~/Documents/mri-test-data/`. | CLAUDE.md section 4: never commit imaging data. |
| 2026-10-03 | Lint/format with ruff, types with mypy (strict), tests with pytest. | CLAUDE.md section 3 offers "mypy or pyright"; mypy chosen as the default. |
| 2026-10-03 | Provenance files are the durable record; SQLite is a rebuildable index. | A broken database must never lose results. |
| 2026-10-03 | File hashes are cached by (path, size, mtime) and recomputed only when those change. | Hashing large 4D scans on every resume check is slow. |
| 2026-10-03 | Interrupted jobs are detected at startup using the recorded process ID plus process start time. | Survives reboots and reused process IDs. |
| 2026-10-03 | FSL is **not** tied to a fixed path. Lookup order: app setting, then `FSLDIR` environment variable, then common install locations. If none works, show a clear message explaining where to set it. The runner builds the FSL environment from the resolved location. | The app must run on other machines. |
| 2026-10-03 | Provenance stores workspace-relative paths. | Workspaces stay movable/copyable. |
| 2026-10-03 | Sessions (`ses-*`) are optional; omitted from paths when absent. | Keeps single-scan workspaces simple. |
| 2026-10-03 | `fsl_anat` is one step; an interrupted run restarts from the beginning. | Simple and safe. |
| 2026-10-03 | The app must work both with and without fieldmap data. Fieldmap correction is offered only when fieldmaps exist (CLAUDE.md principle 9). | User requirement. |
| 2026-10-03 | No user accounts or login system. | Out of scope per CLAUDE.md section 9. |
| 2026-10-03 | Each step run writes `provenance.json` (including failed, interrupted and cancelled runs). The worker deletes the old record before running, so a stale "Completed" record can never be trusted after a crash. | Principle 4 (provenance for every run) and principle 5 (resume must be safe). |
| 2026-10-03 | A previous run is reusable only if its provenance says Completed, it is the latest job for that output folder, version and parameter hash match, input hashes match, outputs exist, pass `validate_outputs` and still match their recorded hashes. | Architecture section 7, plus a tamper check on outputs. |
| 2026-10-03 | Downstream invalidation is two-layered: input hashes (automatic) and, inside a pipeline, any step that reruns forces all steps that use its outputs to rerun, even if the new output is byte-identical. | CLAUDE.md: "if an upstream step changes, downstream steps are invalidated". |
| 2026-10-03 | Output folders are named by a `label` (default: the step name; pipelines use the step id) so one step can appear twice for the same subject. | Needed for pipelines and tests with repeated steps. |
| 2026-10-03 | Pipelines are YAML files with `${stepid.outputfield}` references; they run sequentially and stop at the first failure. Resume = run the same spec again. | Smallest design that supports "fail at step 3, then resume". |
| 2026-10-03 | Only one `LocalJobQueue` should drive a workspace at a time. | Two queues could start the same queued job twice; sufficient for one CLI or API process. |
| 2026-10-03 | `bet` is an **optional, independent** step. Its output is never an input to `fsl_anat`; `fsl_anat` always takes the original T1 with skull. | `fsl_anat` does its own brain extraction (from the non-linear registration to MNI; BET only as a rough mask). Its script (FSL 6.0.7.23, `bin/fsl_anat` lines 536-537) skips registration to standard space when told the input is already brain-extracted ("it requires a non-brain-extracted input image"), and the later planned step 5g needs that registration. Not run empirically; based on the script source. |
| 2026-10-03 | Steps that need FSL declare `requires_fsl`; the worker resolves FSL (app setting, `FSLDIR`, common locations) and builds the environment, and records the FSL version in provenance. `mrforge config fsl <path>` sets the location. | Decision "no fixed FSL path"; non-login shells lack `FSLDIR`. |
| 2026-10-03 | Test T1 for FSL tests: series `2_t1w` (192x256x256, 1 mm) from the DICOM set, converted once with dcm2niix into `mri-test-data/nifti/t1w.nii.gz`. | Stage 1 needs a NIfTI T1; real DICOM import is Stage 2. |
| 2026-10-03 | `fsl_anat` step exposes only `image_type` (-t), `strong_bias` (--strongbias) and `subcortical_segmentation` (False adds --nosubcortseg). `--nobet` and other skip flags are not exposed. Output folder is `<step>/anat.anat/`; 13 key outputs are registered (bias-corrected head and brain, brain mask, tissue segmentation and 3 partial-volume maps, linear and non-linear MNI results, T1->MNI warp coefficients, MNI->T1 field, subcortical segmentation). | Verified against `fsl_anat --help` and a real run (22 min on the test T1, FSL 6.0.7.23). The two warp files are what step 5g needs. |
| 2026-10-03 | Before each `fsl_anat` run the step deletes its own leftover `anat.anat/` folder (only inside the step's output folder). `fsl_anat` also leaves stray `imcp.e<PID>`/`imcp.o<PID>` scratch files; they are ignored. | An interrupted run leaves a partial folder and `fsl_anat` refuses an existing one; decision "restart from the beginning". |
| 2026-10-03 | `fsl_anat` refuses a `bet` output as input (error `ANAT_NEEDS_ORIGINAL_T1`, detected from the provenance next to the file) and warns if the file name looks skull-stripped. | See the bet/fsl_anat decision above. |
| 2026-10-03 | Tests marked `slow` (full fsl_anat runs, ~22 min each) are separate: `pytest -m "fsl and not slow"` for quick FSL checks, `pytest -m "fsl and slow"` for the full runs. | Keeps routine test runs short. |
| 2026-10-03 | `fsl_anat` subcortical segmentation (FIRST) is **off by default** (opt-in via `subcortical_segmentation: true`; the default adds `--nosubcortseg`). The 12 other key outputs are always produced. | User decision: slow, and not needed for WM/CSF signal regression, which uses the tissue segmentation. Changing the default changes the parameter hash, so an earlier default run (which included FIRST) is rerun if requested again. |
| 2026-10-03 | **Full BIDS derivatives layout** (user decision): results in `derivatives/mrforge/sub-XXX/[ses-YY/]<datatype>/` with BIDS names; native `fsl_anat` folder named after the input (`sub-001_T1w.anat/`); per-step provenance and logs in `_runs/<label>/`; `dataset_description.json` and `.bidsignore` at `derivatives/mrforge/`. BIDS-named results are hard links to (copies of) the tool's native files. Replaces the earlier `<step>/anat.anat/` layout. | Interoperability with other BIDS tools and a layout lab members recognise. Changes CLAUDE.md section 5 (edited with the user's approval of the direction). |
| 2026-10-04 | Stage 2a: the import manifest lives in `<workspace>/imports/import-NNN/manifest.json`, **not** in `rawbids/.mrforge/` as first planned. | `rawbids/` must stay immutable once written, while the manifest changes when the user corrects a series. `imports/` is a small addition to the workspace layout. |
| 2026-10-04 | The copied DICOMs go to `sourcedata/dicom/import-NNN/` (a neutral name), not under the source's own name. The same source (same file names and sizes) is recognised on a second scan and not copied again. | Folder and ZIP names from scanners often contain the patient name; the import id keeps names out of paths, logs and tables. |
| 2026-10-04 | DICOM headers are read with pydicom `specific_tags` (a fixed list of acquisition tags), in parallel processes. Patient name, ID, dates and institution are never loaded, stored, shown or logged. File paths inside a source are never stored (file names only). | Privacy by construction; tested with synthetic DICOMs carrying fake identifying values. Reading costs about 28 ms per file, so 1064 files take a few seconds in parallel. |
| 2026-10-04 | Volumes are counted per image: enhanced (multi-frame) DICOM has one file per volume with slices as frames; classic DICOM has one file per slice (volumes = files / slices). Echoes and magnitude/phase images are separated using a `dcm2niix -b o` sidecar-only pass (about 4 s for the whole session), which also supplies phase-encoding direction with sign and TR/TE (enhanced headers keep these in private groups). | Found on the real session: all series are enhanced DICOM. Diffusion b-values are not available from the sidecar-only pass; they come at conversion (2c). |
| 2026-10-04 | Stage 2b: series are classified by rules in `classification_rules.yaml` (plain text, packaged with MRForge; a lab can replace it with `<workspace>/imports/classification_rules.yaml`). Confidence counts how many different families of clues agree (text, imagetype, geometry, relation to other series): High = enough agree, Medium = one family, none = no match. A series that matches nothing, or whose matches disagree, is "unknown" and is NOT imported until the user decides. | CLAUDE.md 2b: unknown or low-confidence series are never silently assigned. Rules in a file so classification can grow without code changes. |
| 2026-10-04 | Weak clues cannot decide alone: a relation to another series (for example "an earlier series has the same protocol and size") only counts together with another clue, and the motion-correction rule requires the name `MoCoSeries`. | Found on the real session: the fieldmap phase image looked like a "duplicate" of its magnitude image. |
| 2026-10-04 | A BOLD run needs a task name before import. `resting` becomes `task-rest` automatically; other BOLD runs (here series 19 and 25) wait for `mrforge import set <series> --task <name>`. Scanner-generated series (MoCoSeries, statistical maps, diffusion maps, reports, localizers) are listed but skipped; `import set --type ...` switches one on. | User decision (list but skip) and CLAUDE.md 2b. |
| 2026-10-04 | User decisions are stored as overrides in the manifest, apart from the rules' results, so re-running the rules (`mrforge import classify`) never loses them. Changing a series' type drops labels that belonged to the old type. Allowed labels: `task`, `acq`. | Corrections must persist; the stage checklist asks for exactly this. |
