| 2026-10-04 | Volumes are counted per image: enhanced (multi-frame) DICOM has one file per volume with slices as frames; classic DICOM has one file per slice (volumes = files / slices). | 2026-10-04 | Stage 2b: series are classified by rules in `classification_rules.yaml` (plain text, packaged with MRForge; a lab can replace it with `<workspace>/imports/classification_rules.yaml`). A series that matches nothing, or whose matches disagree, is "unknown" and is NOT imported until the user decides. | CLAUDE.md 2b: unknown or low-confidence series are never silently assigned. Rules in a file so classification can grow without code changes. |
| 2026-10-04 | Weak clues cannot decide alone: a relation to another series (for example "an earlier series has the same protocol and size") only counts together with another clue, and the motion-correction rule requires the name `MoCoSeries`. | Found on the real session: the fieldmap phase image looked like a "duplicate" of its magnitude image. |

| 2026-10-04 | A conversion is checked against the scan: the set of image sizes must match (axis order may differ, because dcm2niix reorders axes, for example the real T1: scan 256x256x192, NIfTI 192x256x256), the volume count must match exactly, the images dcm2niix wrote (echoes, magnitude/phase) must match what the scan expected, a JSON sidecar must exist, and diffusion series need bval/bvec with one b-value per volume. | 2026-10-04 | Stage 2e: the installed npm `bids-validator` 1.15.0 checks `rawbids/` (`mrforge import validate`, also run at the end of `mrforge import run`).
